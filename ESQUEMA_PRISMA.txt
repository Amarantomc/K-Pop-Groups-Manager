NOTAS IMPORTANTES
═══════════════════════════════════════════════════════════════════════════════

1. La base de datos utiliza PostgreSQL como gestor.

2. Las claves foráneas con "Cascade Delete" eliminarán registros dependientes
   cuando se elimine el registro padre:
   - PerfilManager.userId → User(id)
   - PerfilDirector.userId → User(id)
   - PerfilAprendiz.userId → User(id)
   - PerfilArtista.userId → User(id)
   - Ingreso.idAct → Actividad(id)
   - Contrato.(idAp, idGr) → Artista(idAp, idGr)
   - Contrato.idAg → Agencia(id)
   - ContratoGrupo.idAg → Agencia(id)
   - ContratoGrupo.IdGr → Grupo(id)
   - AprendizEnAgencia.idAp → Aprendiz(id)
   - AprendizEnAgencia.idAg → Agencia(id)
   - EvaluacionAprendiz.idAp → Aprendiz(id)
   - EvaluacionAprendiz.idAg → Agencia(id)

3. Las entidades de relación que conforman relaciones muchos a muchos son:
   - AlbumPreemiado (Album-Premio)
   - CancionEnListaDePopularidad (Cancion-ListaPopularidad)
   - AprendizEnAgencia (Aprendiz-Agencia)
   - ArtistaEnGrupo (Artista-Grupo)
   - ArtistaLanzaAlbum (Artista-Album)
   - GrupoLanzaAlbum (Grupo-Album)
   - AprendizSolicitaGrupo (Aprendiz-Solicitud)
   - ArtistaSolicitaGrupo (Artista-Solicitud)

4. Las claves primarias compuestas permiten registros múltiples con validaciones
   en fechas para controlar el historial temporal de las relaciones.

5. Los valores por defecto establecidos:
   - User.role, Actividad.estado, AprendizEnAgencia.estado: Valores predeterminados
   - Aprendiz.fechaNacimiento, Actividad.fecha, Album.fechaLanzamiento,
     Solicitud.fechaSolicitud, Cancion.reproducciones, etc.
